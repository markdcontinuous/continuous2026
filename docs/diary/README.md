# Mark's work diary

One file per working day, kept by Claude. The aim is a second brain: what got done, what was decided, what ideas came up, and what is still open, so nothing is lost between sessions and any day can be replayed in a minute.

## How it works

- **One file per day**: `YYYY-MM-DD.md`. A session that runs past midnight stays in the day it started.
- **Fixed sections in every entry**: Done, Decisions, Ideas, Open, Next. Short lines, no prose. If a section is empty it is left out.
- **When something significant gets decided, the entry also records how we got there**: the problem we were trying to solve, the options on the table, what was rejected and why, and who chose. That block is written in prose, under its own heading ("How we got to X"), because the reasoning is the part that is hardest to reconstruct later.
- **Ideas also go to `IDEAS.md`**, the running backlog, so they survive the day they were had. When an idea is built or dropped, it is marked there, not deleted.
- **Claude updates the entry at the end of every session**, and mid-session when a decision or idea is worth keeping. Mark can say "diary" at any time to force an update, or "what did we do on the 24th" to have a day read back.
- **Decisions are Mark's** and are written as his: "Mark: PoC only, about 10 lessons."
- **Project detail stays in the project folders.** The diary points at files, it does not repeat them.
- **Cost**: the diary is not loaded at the start of a session. Only a one-line pointer in Claude's memory says it exists. A day is read only when asked for, so it costs nothing until it is used.
